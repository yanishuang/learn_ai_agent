# 第 14 章：Know-Engine 毕业项目

## 本章定位

Know-Engine 是课程必做的毕业项目，用一个边界清晰的企业知识任务串联文档摄取、RAG、单 Agent、Workflow、MCP、评估、可观测性和生产治理。项目按里程碑复用前面章节的实验，不重新发明一套平行实现。

## 前置知识

Core 前置要求是第 1 章到第 10 章，以及第 13 章；学员应至少达到这些章节的 Core 标准。第 11、12 章只作为 Optional Advanced 输入，不是本项目的必修前置。开始项目整合前，应已有可运行的文档检索、受控工具、单 Agent、持久化 Workflow、评估集和 MCP 客户端或服务端实验。

## 学习目标

- 学员能够交付从文档摄取到带引用回答的端到端系统。
- 学员能够将用户与租户权限注入可信运行上下文，并在检索和工具层执行授权。
- 学员能够用有预算的单 Agent 和可恢复 Workflow 协同完成任务。
- 学员能够提供 MCP 集成、离线评估、脱敏 trace 和生产就绪报告。
- 学员能够通过架构说明、现场演示和失败复盘证明项目可复现。

## 核心知识

项目的核心是把章节能力组合成一条可验证链路：版本化文档进入索引，检索结果保留来源和权限，Agent 在预算内选择工具，Workflow 管理长任务和审批，MCP 提供受治理的外部能力，评估与 trace 记录结果和过程。任何一层都不得绕过后端权限或用模型自报置信度替代证据。

## 教师演示

教师从一条业务问题开始，演示文档入库、权限过滤、检索引用、Agent 工具调用、Workflow 状态、MCP 交互和评估结果如何通过同一请求标识关联。教师还展示一次故意失败的运行，并说明如何从 checkpoint 恢复和生成复盘材料。

## 学员实验

学员按里程碑交付文档摄取与索引、可信 RAG、受控 Agent、持久化 Workflow、MCP 集成、评估与可观测性、产品体验和生产报告。每个里程碑必须包含可运行命令、验收用例、失败证据和更新后的架构说明。

## 失败注入与排错

项目至少注入解析失败、检索无结果、权限拒绝、工具超时、重复副作用、审批内容变化和预算耗尽。学员必须证明系统给出结构化失败、保持状态一致、避免越权或重复执行，并能从 trace 与持久化记录定位根因。

## 自动验证

当前仓库的可执行基线是根目录验证与测试。教学发布版提供 `reference-implementation/` 后，按其 README 用 Fake Model 覆盖模型输出、工具使用、RAG、Workflow 状态、trace 和评估的端到端场景；核心测试必须离线、无密钥且可重复。Live 模式只作为显式启用的补充比较，并记录模型、用量和延迟。

## 作业与评分

毕业项目总分 100 分，其中端到端功能占 25 分，权限与安全占 20 分，评估和可观测性占 20 分，失败恢复占 15 分，复现文档与架构答辩占 20 分。缺少威胁模型、生产就绪报告或离线测试中的任一项，项目不能判定为完成。

## Core / Advanced / Production 完成标准

- Core：完成文档摄取、检索引用、权限过滤、受控 Agent、Workflow、MCP 和离线评估的完整链路。
- Advanced：可加入经过指标证明有效的高级检索或多源路由，并在教学发布版提供后完成显式启用的 Live 对比实验。
- Production：提交威胁模型、容量与成本预算、数据保留、事件响应、CI 门禁和部署回滚证据。

## 本章资料

本章以第 1 章到第 10 章和第 13 章的产出、课程评估标准和生产检查表为主要资料；第 11、12 章可作为 Optional Advanced 参考。引用外部框架或协议时，项目文档必须说明其用途、成熟度、验证日期和退出方案。

## 复盘模板

复盘时请完整回答：哪条用户任务证明系统真正有价值；哪个边界最有效地阻止了错误；哪次失败改变了架构设计；哪些能力达到 Core、Advanced 或 Production；下一次迭代最先降低哪个风险。
