# 第 9 章：Agent 评估、可观测性与安全

## 本章定位

本章把前面完成的模型、工具、单 Agent、RAG 和 Workflow 统一放入可验证的质量与风险体系。学员不再以一次演示成功作为完成标准，而是用数据集、轨迹、指标和安全回归用例持续判断系统是否可靠。

## 前置知识

学员应已完成第 5 章到第 8 章，能够阅读工具调用、检索结果、Agent step 和 Workflow 状态。学员还应理解 pytest 断言、结构化日志和最小权限原则。

## 学习目标

- 学员能够设计包含输入、期望行为、断言和失败标签的评估 case。
- 学员能够测量任务成功率、工具选择、参数准确率、轨迹效率、延迟和成本。
- 学员能够使用 trace 还原模型、工具、检索和 Workflow 的关键决策。
- 学员能够为提示词注入、数据外泄、权限提升、工具投毒、失控循环和 denial of wallet 建立红队用例。
- 学员能够把线上失败整理为脱敏的离线回归样本。

## 核心知识

本章覆盖确定性断言、模型评分器与人工校准的分工，任务级和步骤级指标，trace 关联标识与敏感字段脱敏，以及安全用例的威胁、控制和证据结构。模型自报置信度只能作为解释元数据，不能替代权限、审批或质量判定。

## 教师演示

教师选择同一个 Agent 任务，先展示只看最终答案会漏掉的错误工具调用，再通过 trace 找到根因。随后教师运行一组包含正常、权限拒绝、间接提示词注入和循环预算用例的离线评估，并展示失败如何生成可追踪的回归条目。

## 学员实验

学员为 Know-Engine 建立至少十个确定性 case，覆盖正确回答、正确拒绝、工具参数、引用支持和权限隔离。学员还要为单 Agent 增加轮数、工具次数、延迟和成本统计，并提交一份按失败类型聚合的评估报告。

## 失败注入与排错

学员主动注入错误工具参数、伪造检索指令、跨租户资源请求、重复工具调用和超预算运行。每次排错必须从 trace 证据出发，区分提示词、模型选择、工具实现、权限边界、数据质量和预算配置中的真实根因。

## 自动验证

自动验证应在 Fake Model 模式下运行固定评估集，并对输出 schema、工具选择、参数、拒绝行为、最大轮数和敏感信息脱敏作确定性断言。默认测试不得依赖真实模型，模型评分器实验必须通过单独的显式开关运行。

## 作业与评分

作业总分 100 分，其中评估集覆盖度占 25 分，指标与报告占 20 分，trace 可诊断性占 20 分，安全红队用例占 25 分，线上失败回流设计占 10 分。无法从失败报告追溯到具体 case 和 trace 的提交不得获得满分。

## Core / Advanced / Production 完成标准

- Core：离线评估可重复运行，并覆盖任务成功、工具准确性、权限拒绝和预算停止。
- Advanced：加入经过人工校准的模型评分器，并量化它与确定性断言的分歧。
- Production：建立脱敏 trace、线上告警、失败采样、回归准入阈值和 CI 阻断规则。

## 本章资料

本章资料应优先使用 OpenAI Agents SDK tracing 与 evals 文档、OpenTelemetry 规范、OWASP 面向大模型应用的风险资料，以及 pytest 参数化测试文档。使用任何评分框架时都要记录版本、适用范围和校准方法。

## 复盘模板

复盘时请完整回答：哪个指标最能代表当前任务成功；哪条 trace 暴露了仅看答案无法发现的问题；哪个安全 case 最容易被忽略；我会如何把一次线上失败变成稳定的离线回归测试。
